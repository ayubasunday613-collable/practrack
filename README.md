# PracTrack AI

PracTrack AI is a practical-report platform for PTI Effurun. Technologists create experiments and rubric fields; approved students complete assigned reports and receive AI-assisted marks only after Technologist review.

## Run locally

Requirements: Node.js and npm.

```sh
npm install
npm run dev
```

The public pages can be explored without Supabase credentials. Authentication, dashboards, and saved records require a configured Supabase project.

## Supabase setup

The app uses Supabase Auth, Postgres row-level security, and a private Storage bucket. It starts with no student, experiment, report, or grade records.

1. Create a Supabase project and copy `.env.example` to `.env.local`.
2. Set `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` to your project's URL and public anon/publishable key. Never put a service-role key in a `VITE_` variable or browser code.
3. Apply all SQL files in `supabase/migrations/` in filename order, using the Supabase SQL editor
   or the Supabase CLI. The verified Technologist registration migrations promote
   `discipleshipayubasunday2026@gmail.com` after email confirmation and demote the account if its
   email changes. The student-approval migration grants Technologists update access to student
   profile status only; row-level security continues to restrict which profiles they can update.
4. Enable email confirmations in Supabase Auth. This is required: the account is authorized only
   after Supabase confirms control of `discipleshipayubasunday2026@gmail.com`.
5. Open `/technologist-register` in the app, create the account, and follow the confirmation link
   sent to that email. After confirmation, sign in at `/technologist-login`. The password is set
   in the app and is never stored in the database schema.
6. Restart the dev server after changing `.env.local`.

If Supabase reports an email rate limit, wait for the limit to reset before requesting another
message, or configure custom SMTP in the Supabase Auth email settings. Recreating the database
schema does not reset Auth email limits.

## GitHub Pages deployment

The GitHub Actions workflow builds and deploys the static client whenever a commit is pushed to
`main`. In the repository settings:

1. Add the Actions repository secrets `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` using the
   values from the Supabase project. The anon/publishable key is intended for browser use; never
   use a service-role key.
2. Set **Settings → Pages → Build and deployment → Source** to **GitHub Actions**.
3. In Supabase **Authentication → URL Configuration**, set the Site URL to
   `https://ayubasunday613-collable.github.io/practrack/` and add
   `https://ayubasunday613-collable.github.io/practrack/**` to the allowed redirect URLs.

The app is served from the `/practrack/` project path. Static hosting does not run server code;
authentication and data use Supabase, and AI assessment uses the separately deployed
`assess-report` Edge Function.

## AI assessment setup

AI grading suggestions are generated by the `assess-report` Edge Function. Configure a server-side OpenAI-compatible provider and deploy the function:

```sh
supabase secrets set AI_API_KEY=your-provider-key AI_MODEL=your-model
supabase functions deploy assess-report
```

Optionally set `AI_API_URL` to the provider's chat-completions endpoint. Keep provider keys in Supabase secrets; do not add them to `.env.local` or client code. Submitted report text and Technologist-authored rubrics are sent to the configured provider; sketches are not.

## Workflow and safeguards

- Students register and wait for Technologist approval.
- Technologists author experiments, report fields, required-field rules, maximum marks, and marking criteria before publishing and assigning.
- Each assigned student receives a random, one-time report code. Only its assigned, approved student account can claim it. The code is shown once, stored as a hash, and expires.
- Students can add pages to a report booklet and upload up to five private JPG/JPEG/PNG sketches per report. Text answers block paste as a browser-side deterrent, not proof of authorship.
- AI suggestions are saved as unapproved marks. A Technologist must review/adjust and approve every field before students can see final grades.

The report code binds a report to an account; it cannot prevent a student from sharing their login session or prove who physically authored a report. Live backend flows require the Supabase migration, project credentials, and Edge Function deployment above.
